# 3x-ui 3.8.5 — расширения Happ

Отдельная версия на основе официального тега v3.8.5, коммит
7ef22f94c950ff09f0870e2295fa65ad5968742c. Изменения не относятся к билдеру
server_installer. Автоматический редирект в Happ не добавлен: его обслуживает
существующий Nginx.

## Что добавлено

Настройки панели → Подписка → Happ → Дополнительные настройки:

- скрытие настроек серверов через subscription-hide-server-settings;
- обновление при открытии Happ, включение автообновления, закрепление подписки;
- фрагментация: включение, packets, length, interval, maxsplit;
- шумы: включение, type, packet, delay, applyto;
- результат пинга time/speed;
- сортировка ping/name/country.

Всего 16 отдельных полей. Настройки хранятся в штатной таблице settings под
ключами subHapp*. Они включены в AllSetting, API-схемы, форму и обычное сохранение.
Обработка выполняется в internal/sub/happ.go через HTTP-заголовки, в том же
потоке, что и официальные настройки Happ. Для применения включите автоопределение
Happ: параметры отправляются только при его User-Agent. Выключенные флаги
не отправляются; параметры выключенной фрагментации/шумов также опускаются.
Отсутствие флага не обещает сброс уже сохранённой настройки в приложении.

Входящие → редактирование → Основное → Описание инбаунда (Happ):

- отдельное поле в inbounds, до 1024 символов;
- заполненное описание инбаунда имеет приоритет над описанием хоста в его
  обычных ссылках; пустое сохраняет стандартную обработку хостов;
- VLESS/Trojan/Shadowsocks/Hysteria/TUIC: штатный формат описания 3.8.5
  в хвосте фрагмента ссылки, ?serverDescription=BASE64;
- VMess: текстовое поле serverDescription верхнего уровня JSON;
- JSON/Clash-конфигурации не получают произвольных Happ-полей;
- поле сохраняется при создании/редактировании, новое SQL-поле добавляется
  стандартной миграцией модели. Имеющийся server_description старого форка
  используется под тем же именем.

Штатные баннеры, окончание подписки, тип пинга, маршрутизация и остальные
опции 3.8.5 сохранены. Старый JSON subHappConfig автоматически не мигрируется:
перенесите значения в новую форму. Старый формат meta.serverDescription не
дублируется — используется существующий формат описаний официальной 3.8.5.

## Сборка

Нужны Go 1.27.1+ и Node.js 24+ с npm. Из корня проекта:

```bash
cd frontend
npm ci
npm run gen:zod
npm run build
cd ..
mkdir -p build
go build -trimpath -o build/x-ui .
```

Это полный исходный проект, а не готовый установщик. Официальные команды
install.sh/x-ui update скачивают официальные релизы и не устанавливают эти
расширения. Собирать и выпускать нужно собственный бинарный файл.
Обычное обновление официальным релизом заменит изменённый код.
Перед заменой работающего бинарника сохраните SQLite-базу и текущий бинарник,
остановите x-ui, замените бинарник своей сборкой и запустите сервис.

Архив содержит также happ-v3.8.5.patch — изменения относительно чистого тега.
Для применения к другой чистой копии именно v3.8.5:

```bash
git apply --check /path/to/happ-v3.8.5.patch
git apply /path/to/happ-v3.8.5.patch
```

## Проверено

- go test ./internal/sub ./internal/web/service ./internal/database/model;
- отдельные тесты 16 новых заголовков, ограничения по Happ/AutoDetect,
  очистки CR/LF, отключённых параметров и описаний VLESS/VMess;
- TypeScript typecheck и production-сборка Vite;
- 43 существующих теста форм/Happ, затем 33 теста адаптера формы,
  включая новый round-trip описания (наборы пересекаются);
- сборка исполняемого файла панели.

На настоящем сервере и в мобильном Happ эта версия ещё не проверялась.
Наличие корректного заголовка подтверждено тестами; применение функции
зависит от версии/платформы Happ. Не включайте все сетевые опции одновременно:
сначала проверьте добавление подписки и её обновление на одном клиенте.
